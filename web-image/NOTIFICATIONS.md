# 外部程序通知转发

## 范围

首版支持受信程序提交文字通知，复用当前网页版微信连接，不另行登录。
程序原有的 Telegram 推送保持独立；此入口不是 Telegram Bot API 代理，也不监听机器人自己的消息。
图片、附件、EFB 内部图片复用和第三方机器人消息不在首版范围内。

## 开关和限制

- 总开关、每个绑定的开关默认关闭。每个来源使用独立密钥，只能访问授权绑定。
- Telegram 私聊 `/notify` 查看状态、切换总开关及已配置绑定的开关。
- 开关变更取消等待中的通知，不会在重新开启后补发旧通知。在途请求无法撤回。
- 全局至少间隔 10 秒，同一绑定至少间隔 30 秒。等待队列最多 100 条，每条最多 4000 字符。
- 只在普通消息队列为空、当前没有消息处理中且最近 5 秒无普通消息活动时开始投递。通知使用独立线程，不阻塞普通消息处理线程；在途请求不能抢占取消。
- 通知默认有效期 120 秒，最多 300 秒。离线期间等待；到期丢弃，不集中补发。
- 方案切换取消待发通知。进程重启取消待发通知，未取得结果的在途通知标记为 `unknown`。
- 绑定必须唯一，并在提交、出队及发送前复核。绑定变化后停止该通知，不猜测新收件人。
- 同一来源和 `event_id` 只处理一次。相同编号但内容不同返回冲突；超时或结果不明不自动重发。
- 单个请求超过 20 秒标记为 `unknown`，不启动第二个通知发送线程。原请求可能稍后完成，仍不重发。
- 历史账本最多 10000 条，达到上限拒绝新增，需要人工维护；不自动删除去重证据。

## 接入

入口默认仅监听 NAS 本机，不对公网开放。接入远端程序前单独确定私网可达方式与来源。
密钥放在受限配置或 HA 的 secrets 中，不写进 Telegram、命令行参数或仓库。

`POST /v1/notifications`，使用 `Authorization: Bearer <来源专用密钥>`。

```json
{
  "source": "已配置来源",
  "event_id": "由源程序生成且重试时保持不变的编号",
  "route": "已配置绑定名称",
  "origin": "external",
  "text": "通知内容",
  "ttl": 120
}
```

返回 `202` 表示已入队，不代表微信已收到。相同请求再次提交返回账本现有状态，不再次发送。
`sent` 表示微信发送接口已返回结果，不代表对方已阅读。
`unknown` 表示投递结果不明确，不应生成新编号自动重试。
`401/403` 为来源或绑定未授权，`409` 为绑定或编号冲突，`429` 为队列满，`503` 为关闭或暂不可用。
程序应隔离原有 Telegram 推送和这个附加请求：附加请求失败不能阻塞原有通知。

## 回退

部署前保存配置、绑定数据库一致性副本、控制程序、容器信息和原镜像摘要，逐个文件记录 SHA-256。

第一层：在 `/notify` 关闭通知总开关，无需重启微信，普通转发继续工作。
第二层：主机运行 `notification_switch.py off --root <部署目录>`，效果相同。
第三层：用 `notification_switch.py rollback --root <部署目录> --backup <基线备份目录>` 预览回退计划；核对后加 `--apply` 恢复旧镜像。

镜像回退仅恢复程序版本，不恢复旧数据库，不覆盖后续聊天、绑定或登录记录。回退会短暂重建网页版容器；必须重新检查心跳和登录状态，不能保证不需要扫码。
备用数据库只用于故障恢复，不能作为日常切换版本的覆盖源。
