Managed control candidate

Default managed_control=false preserves legacy text/image behavior. The production config is private and excluded from this candidate.

Managed worker calls control_sync then control_ack with integer revision/epoch, actual local enabled, local image preference images_enabled (can remain true while bridge is closed), and one of NAS accepted phases. Only {acknowledged:true} confirms an ACK. A closed manual worker remains alive on a 15-second interval; active interval is 5 seconds and failed connections back off to 30 seconds. No launch agent/autostart is installed. NAS UI must require fresh revision/epoch-matching acknowledgement (<45 seconds), not infer success from desired state alone.

Managed control never issues on/off while applying a desired snapshot. Only explicit desktop operations use legacy on/off; a failed explicit desktop close remains fenced and is reconciled before accepting new remote state. A desktop close races safely with sync/ack, using off_requested fencing. Missing or rejected ACK fences forwarding; reconnect/epoch changes reset text and image start to now. Image re-enable or any new desired revision resets only the image floor, including a rapid off/on that occurred between polls. No historical message retry; persistent ledger remains unchanged, including unknown events.

Image bytes use the already installed private SSH streaming transport. JPEG/PNG and existing size/age limits remain. Active transmissions can outlast ACK freshness; UI must show waiting/pending while no fresh confirmation exists. No test message is generated by this candidate or installer.

activate_managed.py defaults to a read-only status/source-hash check. --activate backs up only the independent worker/config plus an audit snapshot of its ledger, locally fences it, stops its exact process group (including SSH children), copies code, enables managed_control, and manually starts the independent worker from now. It does not call on/off or restart NAS/EFB/Telegram/WeChat. Backup state-audit.db must never be restored to production: retain current dedupe ledger during rollback. If activation fails, remain paused and inspect backup before explicit recovery.

Validation: python3 -m unittest discover -s this-directory -q (86 tests). All controls/messages/attachments in tests are synthetic mocks. Real pictures require two NEW user-sent pictures, one on each side, after activation; do not replay a prior picture as a test.
