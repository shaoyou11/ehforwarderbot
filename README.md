# EFB 微信转 Telegram 镜像

这是 `shaoyou11` 维护的 EFB Docker 镜像，用于通过 ComWechat 将微信消息双向转发到 Telegram。
镜像保留原部署方案，并针对家庭 NAS、本地 Telegram Bot API、微信登录恢复、中文操作和媒体消息进行适配。

## 组件

| 组件 | 作用 |
| --- | --- |
| EFB Core | 调度主端、从端和中间件之间的消息。 |
| EFB Telegram Master | 在 Telegram 中展示和发送微信消息。 |
| EFB ComWechat Slave | 连接 Windows 微信，处理联系人和微信消息。 |
| 本地 Telegram Bot API | 在 NAS 内提供 Bot API，避免 EFB 按公网 Bot API 默认的 20 MB 上限提前拦截。 |
| WeChat Session Watchdog | 检测可恢复的微信退出界面，并尝试自动进入微信。 |
| EFB Map Middleware | 在重建或迁移后恢复 EFB 会话映射。 |

## 主要能力

- 双向转发微信文字、图片、文件、语音、视频、链接和引用消息。
- 解析微信视频号分享；无法取得原视频时发送封面和可打开的页面链接。
- 图片优先等待原图，确认原图不可用后才尝试缩略图。
- 合并历史失效媒体提醒，避免同一时间发送大量超时消息。
- 自动将微信联系人、群聊和系统账号名称转换为中文名称。
- 提供中文 Telegram 命令菜单、微信管理面板和错误提示。
- 支持本地 Telegram Bot API 的大文件传输路径。
- 支持微信离线提醒、全天事件恢复和凌晨自主检测。
- 支持地图、关键词替换、关键词回复和消息合并中间件。
- 自动构建多架构 Docker 镜像。

## Telegram 命令

| 命令 | 作用 | 说明 |
| --- | --- | --- |
| `/login` | 获取微信登录二维码。 | 微信已登录时直接提示登录成功。 |
| `/wechat` | 打开微信管理面板。 | 支持重新扫码、强制退出、自动恢复设置和关闭。 |
| `/watchdog` | 管理自动恢复。 | 可分别控制总开关、全天事件恢复和凌晨自主检测。 |
| `/bridge` | 管理 Bridge 投递队列。 | 仅管理员私聊可操作；支持查看、重试、重新投递或放弃。 |
| `/namespoiler` | 设置群成员姓名隐藏。 | 默认关闭。 |
| `/chat` | 创建微信会话入口。 | 可附加关键词或正则表达式筛选。 |
| `/link` | 将微信会话绑定到 Telegram 群组。 | 适合长期独立管理联系人或群聊。 |
| `/unlink_all` | 解除当前群组的全部绑定。 | 不删除 Telegram 云端消息。 |
| `/info` | 查看当前 Telegram 会话信息。 | 用于确认绑定和会话标识。 |
| `/update_info` | 更新绑定群组资料。 | 机器人需为管理员，群组应为单一绑定。 |
| `/react` | 回应消息或查看回应者。 | 需回复目标消息。 |
| `/rm` | 删除远程会话中的对应消息。 | 是否成功取决于微信端能力。 |
| `/help` | 显示中文命令说明。 | Telegram 命令菜单也会同步显示。 |

兼容命令：`/extra` 当前打开 `/wechat`，`/0_reauth` 和 `/h_0_reauth` 保留旧的重新扫码用法。
旧命令中的数字是 EFB 动态组件序号，可能随组件顺序变化；日常使用优先选择 `/login` 和 `/wechat`。

## Bridge 队列

`/bridge` 仅管理员可在私聊中使用。活动消息中的 `staged` 表示仍在等待附件或排序，`inflight` 表示正在被 EFB 处理；
这两类状态不会被批量强行改动。

管理开关默认关闭，持久化在：

```text
/data/operations/state/bridge-queue-settings.json
```

关闭时仍可查看队列，但重试、重新投递和放弃会被拦截；开启后，单条和批量操作仍需二次确认。
“放弃”不会直接删除 SQLite 记录，而是保留去重标记和最小审计字段，清空消息正文并标记为 `discarded`。

## 投递明细

`/status` 中的“投递明细”按页列出待处理附件和失败投递：

- 待处理记录支持查看、确认后立即投递或删除。
- 立即投递会跳过附件稳定等待。
- 删除只移除 ComWechat 待发记录，不删除微信原文件。
- 失败记录支持查看、确认后重新投递或删除。
- 删除失败记录只清理 EFB 失败记录和失败副本，不影响微信原文件。

## 微信管理与自动恢复

发送 `/wechat` 后可以使用：

- `重新扫码登录`：调用 ComWechat 登录接口获取二维码。
- `强制退出微信`：执行前再次确认。
- `自动恢复设置`：进入 Watchdog 开关面板。
- `关闭`：删除本次管理面板消息。

Watchdog 的三个设置如下：

| 设置 | 行为 |
| --- | --- |
| 总开关 | 控制全部自动恢复功能。 |
| 全天事件恢复 | EFB 检测到微信离线后触发复核和恢复。 |
| 凌晨自主检测 | 每天 `02:50–03:50` 每 2 分钟主动检查一次。 |

恢复时先复核微信状态，只处理仍保留本机会话、可以点击“确定”和“进入微信”的情况。
如果微信提示自动登录失效或必须重新扫码，Watchdog 停止重复点击并保留诊断信息，不能绕过微信服务端风控。

## 图片、视频和文件

- 本地 Bot API 开启后，EFB 不再按公网 Bot API 默认的 20 MB 上限提前拦截文件。
- 实际可传输大小仍受本地 Bot API、Telegram 服务端、NAS 空间和网络稳定性限制。
- 普通图片优先按消息 ID 调用 ComWechat CDN 接口主动下载原文件，并作为 Telegram 文件发送，避免二次压缩。
- 普通视频沿用微信电脑端自动下载流程；ComWechat 无法取得手机中未经微信转码的原视频。
- 主动下载的媒体文件需连续 3 秒大小不变后才发送，避免转发下载中的文件。
- 视频号原视频下载失败时，保留封面和可点击页面链接；不存在原视频时不伪造下载地址。

## 数据与持久化

需要通过 Compose 挂载保存的内容包括：

- `profiles/`：EFB、Telegram 主端、ComWechat 和中间件配置。
- `author-name-spoiler.json`：群成员姓名隐藏开关，默认关闭。
- `comwechat/Files/`：Windows 微信文件、媒体缓存和发送临时文件。
- EFB 数据库：会话绑定、消息映射和中间件状态。
- Watchdog 状态文件：自动恢复开关和诊断记录。

Telegram 聊天记录保存在 Telegram 云端，可在多个 Telegram 客户端同步。本地 Telegram Bot API 负责上传和下载，
不会把 Telegram 变成本地聊天系统。

删除 NAS 上的 EFB 数据不会删除 Telegram 云端聊天记录，但可能造成微信会话绑定、回复、撤回、引用映射和媒体缓存丢失。

## 镜像与更新

```text
ghcr.io/shaoyou11/efb:latest
```

镜像中的核心组件使用固定 Git 提交构建；`latest` 只指向通过自动构建的最新组合。部署更新前应备份 Compose、配置和旧镜像标识，
再执行有序重启。部署配置示例位于：

- `docker-compose.web.yaml`
- `docker-compose.yaml`
- `profiles/`

实际 Bot Token、管理员 ID、本地 Bot API 凭据和微信数据不得提交到公开仓库，应保存在私有配置仓库或 NAS 持久化目录。

## 故障排查

1. `/login` 无响应：检查 EFB、本地 Bot API 和 ComWechat 是否处于同一个共享网络命名空间。
2. 容器健康但命令无响应：检查 ComWechat 是否曾单独重启；必要时执行完整有序恢复。
3. 能获取二维码但无法登录：查看 Windows 微信是否要求手机确认或提示自动登录失效。
4. 图片或语音下载超时：确认 Windows 微信文件目录可写、网络正常且原文件已下载。
5. Telegram 菜单没有更新：重新打开机器人会话，并检查 EFB 启动日志中的菜单更新结果。

## 维护边界

- 公开仓库只保存源码、示例配置和构建流程。

- NAS 正式更新前建立带时间戳备份并生成 SHA-256 校验文件。
