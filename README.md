# EFB 微信转 Telegram 镜像

这是 `shaoyou11` 维护的 EFB Docker 镜像，用于通过 ComWeChat 将微信消息双向转发至 Telegram。项目保留原部署方案，并针对家庭 NAS、本地 Telegram Bot API、微信登录恢复、中文操作和媒体消息进行了适配。

## 项目组成

| 组件 | 作用 |
| --- | --- |
| EFB Core | 负责主端、从端和中间件之间的消息调度 |
| EFB Telegram Master | 在 Telegram 中展示和发送微信消息 |
| EFB ComWechat Slave | 连接 Windows 微信、处理联系人和微信消息 |
| 本地 Telegram Bot API | 在 NAS 内提供 Bot API，并解除 EFB 默认的 20 MB 判断 |
| WeChat Session Watchdog | 检测可恢复的微信退出界面并尝试自动进入微信 |
| EFB Map Middleware | 在重建或迁移后恢复 EFB 会话映射 |

## 主要功能

- 微信文字、图片、文件、语音、视频、链接和引用消息双向转发
- 微信视频号分享解析，无法取得原视频时提供封面和可打开的页面链接
- 图片优先等待原图，确认原图不可用后才尝试缩略图
- 历史失效媒体合并提醒，避免同一时间大量发送超时消息
- 微信联系人、群聊及系统账号名称自动中文化
- Telegram 命令菜单、微信附加功能和错误提示中文化
- 本地 Telegram Bot API 大文件适配
- 微信离线提醒、全天事件恢复和凌晨自主检测
- 地图、关键词替换、关键词回复和消息合并中间件
- 多架构 Docker 镜像自动构建

## 常用 Telegram 命令

| 命令 | 作用 | 说明 |
| --- | --- | --- |
| `/login` | 获取微信登录二维码 | 微信已登录时会直接提示登录成功 |
| `/wechat` | 打开微信管理面板 | 包含重新扫码、强制退出、自动恢复设置和关闭 |
| `/watchdog` | 管理自动恢复开关 | 可分别控制总开关、全天事件恢复和凌晨自主检测 |
| `/chat` | 创建微信会话入口 | 可在命令后附加关键词或正则表达式筛选 |
| `/link` | 将微信会话绑定到 Telegram 群组 | 适合长期独立管理某个联系人或群聊 |
| `/unlink_all` | 解除当前群组的全部绑定 | 不会删除 Telegram 云端消息 |
| `/info` | 查看当前 Telegram 会话信息 | 用于确认绑定和会话标识 |
| `/update_info` | 更新绑定群组资料 | 机器人需为管理员，且群组应为单一绑定 |
| `/react` | 回应消息或查看回应者 | 需回复目标消息使用 |
| `/rm` | 删除远程会话中的对应消息 | 需回复目标消息，是否成功取决于微信端能力 |
| `/help` | 显示中文命令说明 | Telegram 命令菜单也会同步显示中文简介 |

兼容命令：

- `/extra`：旧的附加功能入口，当前会打开 `/wechat` 中文管理面板。
- `/0_reauth`：旧的直接重新扫码命令，继续保留兼容。
- `/h_0_reauth`：旧的重新扫码用法说明命令，继续保留但不再展示。

旧命令中的数字是 EFB 动态组件序号，可能随组件顺序变化。日常使用请优先选择固定的 `/login` 和 `/wechat`。

## 微信管理面板

发送 `/wechat` 后可以使用以下按钮：

- `重新扫码登录`：调用 ComWechat 原有登录接口获取二维码。
- `强制退出微信`：执行前会再次确认，防止误触。
- `自动恢复设置`：进入 Watchdog 开关面板。
- `关闭`：删除本次管理面板消息。

新入口仅处理 Telegram 配置中的管理员请求。

## 自动恢复逻辑

Watchdog 提供三个独立设置：

| 设置 | 作用 |
| --- | --- |
| 总开关 | 控制全部自动恢复功能 |
| 全天事件恢复 | EFB 检测到微信离线后，通过容器内部接口触发复核和恢复 |
| 凌晨自主检测 | 每天 `02:50-03:50` 每 2 分钟主动检查一次 |

恢复时先复核微信状态，只处理仍保留本机会话、可以点击“确定”和“进入微信”的情况。如果微信明确提示自动登录失效或必须重新扫码，Watchdog 会停止重复点击并保留诊断信息，不能绕过微信服务端风控。

## 图片、视频和文件

- 本地 Bot API 开启后，EFB 不再按公网 Bot API 的默认 20 MB 上限提前拦截文件。
- 实际可传输大小仍受本地 Bot API、Telegram 服务端、NAS 空间和网络稳定性限制。
- 普通图片和视频会优先按消息 ID 调用 ComWechat CDN 接口主动下载原文件；接口失败时继续使用原有等待流程。
- 主动下载的媒体文件需连续 3 秒大小不变后才发送，避免下载中的图片或视频被提前转发。
- 视频号分享若只有缩略图或封面，EFB 无法还原不存在的原视频，会改发封面和可点击页面链接。
- 视频号原视频下载失败时，会保留封面和可点击页面链接。
- 图片默认优先发送主动下载的原图；原图明确不存在时才使用缩略图。

## 数据与持久化

需要持久化的内容应通过 Compose 挂载保存：

- `profiles/`：EFB、Telegram 主端、ComWechat 和中间件配置。
- `comwechat/Files/`：Windows 微信文件、媒体缓存及发送临时文件。
- EFB 数据库：会话绑定、消息映射和中间件状态。
- Watchdog 状态文件：自动恢复开关和诊断记录。

Telegram 聊天记录仍保存在 Telegram 云端，可在多个 Telegram 客户端同步。本地 Telegram Bot API 只负责消息上传和下载，不会把 Telegram 变成本地聊天系统。

删除 NAS 上的 EFB 数据不会删除 Telegram 云端聊天记录，但可能造成以下影响：

- 已绑定微信会话与 Telegram 群组的映射丢失。
- 回复、撤回、引用等依赖旧消息映射的功能失效。
- 微信媒体缓存和 Watchdog 诊断文件丢失。

## 镜像与更新

```text
ghcr.io/shaoyou11/efb:latest
```

镜像中的核心组件使用固定 Git 提交构建，`latest` 只指向已经通过自动构建的最新组合。部署更新时应先备份 Compose、配置和旧镜像标识，再执行有序重启。

部署配置示例位于：

- `docker-compose.web.yaml`
- `docker-compose.yaml`
- `profiles/`

实际 Bot Token、管理员 ID、本地 Bot API 凭据和微信数据不得提交到公开仓库，应保存在私有配置仓库或 NAS 持久化目录。

## 故障排查

1. `/login` 无响应：检查 EFB、本地 Bot API 和 ComWechat 是否处于同一个共享网络命名空间。
2. 容器显示健康但命令无响应：检查 ComWechat 是否曾单独重启；必要时执行完整有序恢复。
3. 能获取二维码但无法登录：查看 Windows 微信是否要求手机确认或提示自动登录失效。
4. 图片或语音下载超时：确认 Windows 微信文件目录可写、网络正常且原文件确实已下载。
5. Telegram 菜单没有更新：重新打开机器人会话，并检查 EFB 启动日志中的菜单更新结果。
